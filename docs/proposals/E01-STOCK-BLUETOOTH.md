# 亿咖通 E01 原厂蓝牙补丁：449 固件源码集成方案

状态：待评审；本 PR 只提交设计，不改变运行行为、不包含固件或安装器。

基线：`657a145`（v0.3.12），2026-11-01 从 origin/main 拉取。

## 问题与目标

当前 `CarPlayBluetoothManager` 构造 Android、HSAE 和 USB 三种适配器；
`HybridBluetoothAdapter.openRfcommStream()` 没有面向原厂 GOC SPP socket 的实现。
449 实车上的原厂蓝牙由 GOC 服务管理，不能把 Android 蓝牙开关可用、电话已连接或 socket 存在当作 iAP2 可用。
目标是在用户明确选择后，通过原厂蓝牙完成 iAP2 引导，复用现有原厂热点和 CarPlay 会话流程。

首批仅支持已验证的 ECARX FE-6 / `xea406m` / Android 5.1 API 22 / 449 固件组合。
“E01”“亿咖通”或 API 22 单一标签不能作为安装依据；其他固件保留原有连接行为。

## 源码接入

建议新增的类型名称均为设计占位，并非当前已实现接口。

1. `shared/.../bluetooth/EcarxGocBluetoothAdapter.kt` 实现现有 `CarPlayBluetooth`。
   配对列表、本机地址和连接状态从匹配版本的 `NfServiceBluetooth` Binder 读取；
   核对 descriptor、transaction、参数和回调 ABI，不能仅根据服务名猜测协议。
   Binder 调用在后台单飞执行并提供总超时；超时不代表底层调用已取消，不反复创建阻塞线程。
   维持必要的服务绑定生命周期，防止最后一次解绑意外停止原厂服务。
2. `shared/.../transport/GocSppDuplexStream.kt` 实现 `BlockingDuplexByteStream`。
   原型使用 `LocalSocket` RESERVED namespace 的 `goc_spp`，连接后先发送目标手机 MAC 的
   12 字节大写 ASCII（去掉冒号，无换行），随后传送 iAP2 字节流。
   实现前以协议夹具核对这一握手，验证目标地址、UUID和当前固件状态；不能用任意手机地址代替选择结果。
   `recv()` 超时返回 null，EOF 返回空数组，异常抛出 IOException；保留有界缓冲、部分读取、背压、关闭唤醒和幂等关闭。
3. 在 `CarPlayBluetoothManager` / `HybridBluetoothAdapter` 中显式选择路由。
   未启用 GOC 时保留现有 USB/Android/HSAE 行为；用户选定 GOC 后，配对列表、本机地址、状态和传输均来自 GOC。
   同时插入 USB 时按保存的路由选择，不在连接中途自动换栈；失败回到可操作错误状态。
   GOC 分支不调用 Android enable/disable，不抢占原厂串口，也不把 GOC 设备伪装成 Android 配对设备。
4. 审核 `CarPlayController` 的启动、重试、停止与原生 adapter 状态判断，以及 `CarPlayHostActivity` 的 enable/disable 调用。
   两处 `openRfcommStream()` 路径必须使用同一个选定适配器；停止应释放应用 socket，不关闭原厂电话/媒体蓝牙。
   复用既有 iAP2 和热点流程，不绕过权限、认证或会话取消处理；热点切换可能导致 Wi-Fi ADB 断开。
5. 在 `common` 中增加固件状态管理和设置卡片，使用 Kotlin/现有 UI 组件，替代 APK 注入、反射私有方法及强制重启应用。
   系统哈希检查、Binder、Root 操作均在工作线程执行；检测结果与安装结果分离，避免每次 UI 绘制同步读取系统文件。

## 用户流程与操作状态

“亿咖通原厂蓝牙（实验性）”放在 Advanced，通过 `SettingsSection` 和 `filteredSection` 接入；
仅向匹配设备显示。检查失败显示原因，不能把不支持伪装成未配对。
提供检测、选择原厂已配对 iPhone、临时验证、安装、恢复原厂和路由开关。
新增 `settings_*` 字符串覆盖所有现有语言；选择控件遵循现有“标题 · 当前值”形式。

路由默认关闭。启用需要匹配的固件状态、有效本机/手机地址及用户选择；保存失败不得显示成功。
更改只对下次连接生效，保存后调用 `markReconnectNeeded()`。
连接中、正在连接或停止未完成时，拒绝安装/回滚/更换目标手机；以整个会话生命周期判断，不能只看 socket 是否关闭。

状态至少区分 Unsupported、Stock、TemporaryReady、Patched、Installing、Restoring、RestoredAwaitingService、Unknown/Failed。
服务 ready、SPP connected、iAP2 authenticated、AirPlay active、first frame 必须单独报告。
回滚已恢复原厂文件但服务未启动时，关闭 GOC 路由并提示“文件已恢复，服务待恢复”；不能继续显示补丁已安装。
进程重启或 Root 超时后重新读取文件、服务和事务状态，不依据上次 UI 状态宣布成功或盲目重试写操作。

## 临时验证与持久化

先实现临时验证：Root、设备、双哈希、原厂服务、占用及真实 owner PID 均校验通过后获得互斥锁，
停止原厂 init 服务并运行候选。拒绝 PID ≤ 1 或与本次会话无关的 owner。
owner 退出、候选退出、显式停止或租期结束后恢复原厂服务；900 次 sleep 循环只是近似租期。
保留独立恢复入口；不宣称掉电、内核崩溃或监督进程被强杀后一定完成清理。

持久化独立评审，并要求本机临时链路验收通过：

- 检查 Root、准确设备/SDK、原厂或已知候选哈希、占用、分区与 verity 状态；未知状态拒绝写入。
- 首次备份原厂文件并校验，记录权限/属主/安全上下文与原挂载状态；重复安装不得用候选覆盖原厂备份。
- 在同分区写临时文件并校验、同步，停止服务后原子替换，启动并检查进程/socket及短时稳定性。
- 失败恢复安装前文件；已恢复原厂后若服务仍失败，保留原厂文件和恢复说明，不换回故障补丁。
- 恢复入口允许服务已经停止；备份缺失或哈希错误时拒绝写入。事务完成恢复原挂载状态。
- 使用原有 init 服务，不增加开机脚本、不修改 boot/init。断电窗口和离线恢复必须单独验证。

系统补丁卸载与关闭应用路由是两个独立动作，UI 必须说明：退出应用或卸载 APK 不会恢复系统文件。
