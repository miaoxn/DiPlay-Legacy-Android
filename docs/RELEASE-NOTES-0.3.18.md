# DiPlay v0.3.18 — 稳定连线重试预算恢复、音频停滞诊断与USB竞争打点

## 更新内容

### 1. 稳定连线重试预算断开实时结算与自愈保障（Issue IKTCRS）
- **偶发断线自愈锁死修复**：
  - 此前无线启动重试预算的重置依赖于会话运行期间单次的 +60 秒宿主计时检查；当遇到会话代次切换（generation churn）或宿主检查未命中的偶发闪断时，先前稳定运行的证据被直接丢弃，导致重试计数停留在上限 `attempt=5` 并锁定，必须彻底重启应用进程才能恢复自动重连；
  - 优化为在 `disconnected(now)` 时主动结算：凡是首帧到达且持续时间达到稳定门槛（`STABLE_SESSION_MILLIS`）的会话，在断开瞬间立即补还完整的重试预算；
  - 尚未达到稳定门槛的短时异常连线不予重置，避免在不稳定环境下无限盲目重连；用户手动停止重试的状态锁保持独立不变。

### 2. 音频接收停滞诊断事件输出（Issue IKTCRS）
- **静默停发事件精准捕获**：
  - 实车测试发现无线会话中偶发 iPhone 端单方面完全停止发送所有音频数据（底层接收包计数连续数分钟 `rx=0`），而车机侧各流渲染器仍处于就绪活跃状态；
  - 在底层音视频数据统计 `logStatsIfDue` 中为每个渲染器增加连续零接收窗口计数：当连续 3 个窗口（约 15 秒）无任何音频包到达时，输出单次关键诊断日志 `audio starved audioType=...`，并在音频恢复接收时自动重新武装；
  - 显著提升在数万行诊断日志中快速定位 iPhone 音频停滞问题的排查效率。

### 3. USB 认领失败统计与权限暴露窗口打点（Issue IKTCRS）
- **接口抢占失败打点**：
  - 在 `LegacyUsbHostCompat.claim` 中加入进程级失败总计数，并在首次及后续每 10 次失败时稀疏输出接口编号、设备路径与底层错误码（`errno`），彻底解决 Android 9+ 系统框架接口认领返回单一 `false` 无法区分权限丢失还是被原厂多媒体/iPod 服务抢占的问题；
  - 在 USBMUX 最终链路建立诊断行中附带全局累计失败计数 `claimFailureTotal`。
- **权限授予暴露窗口量化**：
  - 在获得 iPhone 的 USB 访问权限时，精确记录并输出从请求发出到用户/系统授予的时间跨度（`granted after Xms`），为分析原厂服务在授权窗口期内的竞争行为提供量化依据。
