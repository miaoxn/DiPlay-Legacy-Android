# DiPlay v0.3.26 — 支持日夜时间窗口回退、蓝牙音乐自动唤醒与连接优化

## 更新内容

### 1. 车载蓝牙音频模式下支持开机与连接时自动打开蓝牙音乐（实验性）
- **解决部分车机需手动打开蓝牙音乐才有声音的问题**：
  - 在开启「通过车辆蓝牙播放 CarPlay 音频」时，许多车机在声音通道切换前保持静音，直到司机手动打开车机自带的蓝牙音乐应用切换音频源；
  - 新增实验性开关选项（默认关闭）：开启后，在车机开机（DiPlay 自启动后）以及 CarPlay 会话连接激活时，自动拉起车机内置的蓝牙音乐应用以触发音频源切换，并在 3 秒后自动将 DiPlay 调回前台；
  - 采用严格启发式算法匹配车机桌面应用列表（必须同时命中蓝牙特征词与音乐特征词），确定性选择目标应用并记录在诊断日志中；当检测到插入 USB 蓝牙适配器时不触发。

### 2. 跟随系统日夜模式支持本地时间窗口回退
- **解决车机未上报日夜状态导致无法切换主题问题**：
  - 许多定制或后装 Android 车机从不上报系统日夜状态，导致「跟随 Android 系统」模式下永远停留在先前应用的主题（通常为深色）；
  - 在「设置 → 显示」中的应用主题选项下方新增独立开关（默认关闭）：开启后，若处于跟随系统模式且车机未上报日夜状态，则主题自动跟随本地时钟窗口切换——18:30 至次日 06:00 为深色，其余时间为浅色；
  - 若车机上报了明确的日夜状态，车机状态始终优先；
  - 主界面通过生命周期感知的延时任务在时间窗口边界（06:00 与 18:30）自动重检，投屏端通过现有的 2 秒轮询机制自动捕获变更，等待界面、三指设置菜单与侧边快捷栏全面联动；已完整提供 7 种语言国际化文案。

### 3. 无线启动重试次数耗尽后保持低频持续寻呼
- **解决车机冷启动后手机慢速唤醒导致连接彻底终止问题**：
  - 原逻辑在启动重试预算耗尽（5 次尝试失败）后会永久锁定，车机端不再发起连接，只能依赖用户手动点击重试、拔插或重新打开应用；
  - 车机重启后 iPhone 往往唤醒较慢，响应到达时重试预算可能已耗尽，导致车主每次上车都必须打开手机蓝牙界面；
  - 新增低频寻呼机制（`armSlowRetryAfterExhaustion`）：在因手机未唤醒或热点未就绪导致预算耗尽后，以 60 秒为周期保持慢速寻呼重试，直至 iPhone 响应或用户手动操作；
  - 严格保持会话代次与状态隔离，设置菜单打开时自动延后，确保连接恢复平滑可靠。

### 4. 设置界面 Toggle 开关行浅色主题文字显示修复
- **修复浅色模式下开关行文字近白隐形问题**：
  - 公共开关行辅助函数此前硬编码传递了深色卡片主题（`SettingsTheme.CARD`），导致在浅色主题下，近白色的标题与描述文字直接绘制在白色卡片背景上而不可见；
  - 改为传递在 `render()` 起始阶段解析出的动态应用主题（`appTheme`），浅色模式下采用深色高对比度文字，深色模式保持原有配色不变。
